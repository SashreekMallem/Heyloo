| Capability | Retell AI (2026-09) | Source |
|---|---|---|
| **Agent types** | 3 engines: **Conversation Flow** (node graph — recommended for structured/high-stakes calls), **Single Prompt** (one prompt, ≤1000 words / ≤5 functions recommended), **Multi-Prompt** (now labeled **legacy** in the dashboard — still works, not for new builds). Plus **Custom LLM** (bring-your-own via WebSocket, voice-only) and **Chat agents** (text; share prompt/tools/KB with voice, headless — no first-party chat UI). | `/build/overview`, `/build/conversation-flow/overview`, `/build/single-multi-prompt/prompt-overview`, `/integrate-llm/overview` |
| **Conversation Flow node types** | Dialogue: Conversation, **Subagent** (new — LLM-driven multi-tool dialogue node, replacing tools-on-conversation-node as of 04/18/2026), Extract DV. Action: Function, Code (JS sandbox, `fetch()`, 20k char cap), SMS, MCP. Call control: Call Transfer, **Agent Transfer** (agent-swap, same `call_id`), Press Digit, End. Logic: Logic Split (always has an else edge), Subflow/**Components** (reusable, sharable across agents). No published node-count cap. | `/build/conversation-flow/node`, `/build/conversation-flow/subagent-node`, `/build/conversation-flow/transfer-agent-node` |
| **Global nodes** | Reachable from anywhere; supports "go back to previous node," "prevent immediate re-trigger" (N node-step cooldown), and example-based fine-tuning (examples must end on a user turn, since global nodes evaluate only after a user turn). | `/build/conversation-flow/global-node` |
| **Flex Mode** | Compiles an entire flow/subflow into one dynamic prompt at runtime (Tasks + Tools) for the flexibility of a single prompt with flow-authored logic. **Materially increases LLM cost** — pushes prompts over the 4,000-token billing threshold (see pricing exceptions below); recommended ≤20 nodes per flex region. | `/build/conversation-flow/flex-mode` |
| **Tools/custom functions — payload shape** | POST/GET/PUT/PATCH/DELETE to your URL. Body: `{name, call, args}` (or args-only with `Payload: args only`). `call` object **always includes `from_number`/`to_number`/`direction`** on phone calls (absent on web calls) — this is the authoritative caller number, matching our canonical `ToolCallRequest.callerNumberE164` design exactly. Also carries `retell_llm_dynamic_variables`, `metadata`, `custom_sip_headers`, full transcript-to-that-point. **Timeout**: 1s–10min, default 2min. **Retries**: off by default, `max_retry` 0–5 with exponential backoff + jitter (only if idempotent — retries repeat the request). **Response cap**: 15,000 chars by default (code-node result cap is also 15,000; workflow-function cap is 15,000 custom-function / 30,000 integration-tool). SSRF-blocked: no localhost/private-IP/cloud-metadata targets. | `/build/single-multi-prompt/custom-function`, `/build/conversation-flow/custom-function` |
| **Tool call signature verification** | `X-Retell-Signature: v={ms_timestamp},d={hex}` — HMAC-SHA256(rawBody + timestamp, apiKey). Must verify against **raw** body (re-serialized JSON breaks it — documented explicitly, matches CLAUDE.md Rule 2's raw-body-first requirement). 5-minute replay-window tolerance documented for the general webhook signature (tool-call verification via SDK `Retell.verify()` doesn't state a tolerance itself but uses the same header format). Outbound Retell IP for tool calls/webhooks/MCP: `100.20.5.228` (allowlist-able). | `/build/single-multi-prompt/custom-function#verify-the-request-is-from-retell`, `/features/secure-webhook` |
| **MCP (both directions)** | (1) Agent **consumes** a remote MCP server mid-call via MCP node (flow) or MCP tool (prompt agents) — Streamable HTTP, headers/query-params only for auth (no OAuth flow — pass a pre-obtained token as a dynamic variable), agent's own outbound IP `100.20.5.228` allowlist-able. (2) Retell **exposes itself** as a hosted MCP server at `https://mcp.retellai.com` (moved from legacy `retell.stlmcp.com`, shut down 07/20/2026) for Cursor/Claude Desktop/Claude Code/Codex to manage the whole account (agents, calls, numbers, KBs, voices, chats, testing/QA, alerts/webhooks) — `Authorization: Bearer <API_KEY>`. | `/build/single-multi-prompt/mcp`, `/build/conversation-flow/mcp-node`, `/get-started/mcp-server` |
| **Knowledge base** | URL (crawl + auto-refresh/auto-crawl every 24h), File (25 files/50MB/50MB each; CSV/TSV/XLS/XLSX capped 1000 rows × 50 cols), Text (50 snippets), Google Drive/OneDrive/Notion sync. 500 URL cap per KB; multiple KBs per agent to scale past limits. Node-level KB (Conversation Flow) merges with agent-level. Retrieval: 1–10 chunks (default 3), similarity threshold default 0.60, optional "Knowledge Base Instruction" (≤500 chars) to steer the pre-retrieval query-rewrite step. Retrieved chunks visible per-turn in call transcript ("Knowledge Base Retrieval" link). Retrieval latency **<100ms** claimed. | `/build/knowledge-base` |
| **Phone numbers — provision** | Retell-managed purchase (US/Canada only, Twilio or Telnyx backing, $2/mo, $5/mo toll-free); **BYO via elastic SIP trunking** (Twilio/Telnyx/Vonage guides, "no charge for custom telephony," IP allowlist `18.98.16.120/30` + 3 more CIDRs, TCP/UDP/TLS/mTLS, PCMU/PCMA/G.722); **dial-to-SIP-URI** fallback for providers without elastic trunking (loses native transfer support); contact-center connectors for Avaya, Genesys Cloud, Five9, Amazon Connect. | `/deploy/purchase-number`, `/deploy/custom-telephony` |
| **Phone number → agent binding** | As of 03/31/2026, single-agent fields (`inbound_agent_id` etc.) are **deprecated in favor of weighted agent lists** (`inbound_agents`, `outbound_agents`, `inbound_sms_agents`, `outbound_sms_agents` — each `{agent_id, agent_version, weight}`) — this **is** Retell's native A/B-testing/dynamic-multi-agent-per-number mechanism, separate from and complementary to the inbound webhook's per-call `override_agent_id`. | `/deprecation-notice/2026/03-31_phone_number_agent_fields`, `/deploy/ab-testing` |
| **Inbound call/SMS webhook** | Per-**phone-number** config (not per-agent/account — those are for call-lifecycle events). `POST` with 10s timeout, 3 retries. Payload always includes `from_number`/`to_number`; includes `agent_id`/`agent_version` if the number has one set; includes a **pre-allocated `call_inbound.call_id`** (stable across retries) — confirms our canonical `InboundCallContext.providerCallId` optionality is correct (no call object exists yet). Response can set `override_agent_id`, `override_agent_version`, `dynamic_variables`, `metadata`, **`agent_override`** (a rich partial-config override object touching ~25 voice-agent fields and Retell-LLM/conversation-flow fields, session-scoped only, never persisted), or `reject: true` (works even when the number has a default inbound agent — added specifically to fix the older "omit override_agent_id" pattern). No response within timeout+retries → falls back to the number's default inbound agent if set, else disconnects. | `/features/inbound-call-webhook` |
| **Outbound calls** | `POST create-phone-call` v2: `from_number`, `to_number`, `override_agent_id`/`_version`, `agent_override`, `metadata`, `retell_llm_dynamic_variables` (**string values only** — cast in code), `custom_sip_headers`, `ignore_e164_validation` (custom telephony only). KYC (Persona or automatic) **required before outbound calling, number purchase, or SMS**. CPS defaults: Twilio 1 (max 5, ~10min to change), Telnyx 1 (max 16, instant), Custom Telephony 1 (max 150). | `/deploy/outbound-call`, `/accounts/kyc` |
| **Batch calling** | CSV upload (phone_number column + arbitrary dynamic-variable columns + reserved `override agent id/version`, `metadata`, `custom_sip_headers`, `ignore e164 validation`), scheduled or immediate, reserved-concurrency slider so batch traffic doesn't starve inbound/other calls. `create-batch-call` returns only `batch_call_id` — per-call `call_id`s require `list-calls` filtered by `batch_call_id`. Batch calls **count toward concurrency** and are throttled by CPS like any outbound call. Cost: **$0.005/dial** flat (pricing page). | `/deploy/make-batch-call` |
| **Voicemail / IVR detection** | **Outbound-only** (no-op on inbound — a person is calling you). Continuous detection within a timeout window, first **3 minutes of the call only**. Voicemail: Hang up, or Leave a message (Prompt or Static, dynamic-variables supported). Separate **IVR Hangup** toggle (distinct from IVR *navigation* via Press Digit tool/node). Added latency **<30ms**. | `/build/handle-voicemail` |
| **Transfers** | **Cold** (SIP INVITE default, or SIP REFER), **Warm** (agent stays, human-detection + auto-greet + whisper/three-way messages, configurable ring/timeout), **Agentic Warm** (a *second, dedicated* transfer-agent — cannot itself End/Transfer/AgentTransfer, only Bridge or Cancel — screens the destination two-way before deciding to bridge; separate from Agent Transfer). **Agent Transfer / "agent swap"**: near-zero-latency handoff to *another Retell agent* on the **same call_id**, no new phone call, inherits full transcript/metadata/dynamic-variables; cannot target a custom-LLM or chat-channel agent. Caller-ID override supported on Retell Twilio numbers (both cold/warm) and Retell Telnyx (cold only, SIP REFER). Custom SIP headers forwarded on transfer (`X-*` or `User-To-User`), stripped when the far end is PSTN not SIP. Billing: AI-agent fee stops the moment the caller connects to the destination; only telephony continues. | `/build/conversation-flow/call-transfer-node`, `/build/single-multi-prompt/transfer-call`, `/build/single-multi-prompt/transfer-agent` |
| **Post-call analysis ("Post Call Extraction")** | **Built into the base platform, no separate line item** (this resolves the ambiguity flagged in the prior research pass — see §7). Built-in fields: `call_summary`, `user_sentiment`, `call_successful`, `in_voicemail`. Custom fields: Boolean / Text / Number / Selector(enum), each with a name + LLM-facing description. Runs *after* `call_ended`; results land in `call_analysis`, delivered via the separate `call_analyzed` webhook (NOT included in `call_ended`'s payload — a real footgun to flag in our own event-handler code). Rerunnable per-call or backfilled in bulk after editing config. Not populated for calls that never connected. | `/features/post-call-analysis-overview`, `/features/post-call-analysis-consumption` |
| **AI QA (separate paid product)** | A **distinct, sampled, cohort-based** quality-scoring product — NOT the same as Post Call Extraction. Define a cohort (agents/date-range/duration/disconnection-reason/PCE filters + sampling % + weekly cap) and resolution criteria (AI-evaluated conditions + performance-metric thresholds: latency, sentiment, overlapping speech, WER, hallucination rate, tool-call accuracy, node-transition accuracy, agent naturalness), with optional weighted scoring and manual calibration overrides. **Pricing: first 100 min/workspace free, then $0.10/min of analyzed call time** — confirmed exact, resolves prior doc's flagged ambiguity. | `/ai-qa/overview`, `/ai-qa/create-cohort`, `/ai-qa/define-resolution-criteria` |
| **Webhooks — event types** | Voice: `call_started` (not fired if the call never connected), `call_ended`, `call_analyzed`, `transcript_updated` (per-turn + final), `transfer_started`/`transfer_bridged`/`transfer_cancelled`/`transfer_ended`. Chat: `chat_started`, `chat_ended`, `chat_analyzed`. Configurable via `webhook_events` per agent (defaults: `call_started`/`call_ended`/`call_analyzed`). Two registration scopes: **account-level** (dashboard) and **agent-level** (`webhook_url` field — overrides account-level for that agent entirely, not additive). Both URL fields support `{{dynamic_variables}}`. 10s timeout, 3 retries, delivered in order but non-blocking (a failed `call_started` doesn't block `call_ended`). | `/features/webhook-overview` |
| **Webhook signature verification** | Same HMAC-SHA256 scheme as tool calls: `X-Retell-Signature: v={ts_ms},d={hex}` over `rawBody+timestamp`, keyed on the API key with the "webhook badge" (one key per workspace is auto-designated and cannot be deleted). **5-minute replay tolerance is explicit here.** Full from-scratch reference implementations given in Go, Ruby, PHP (beyond the official Node/Python SDKs) — useful if we ever need a non-JS/Python edge runtime. | `/features/secure-webhook` |
| **Voices / TTS** | Providers: Retell Platform (own curated library, auto TTS-fallback built in, no separate config needed), MiniMax, Cartesia, Inworld, Fish Audio, ElevenLabs, OpenAI. Non-platform voices need manual TTS-fallback config. Custom voice cloning (`clone-voice` API) can target `platform` provider to inherit auto-fallback. **Expressive Mode** (platform voices only): auto emotion/effect/emphasis tags (empathetic, excited, sigh, pause, stress-emphasis) in 13 languages, overridable per-tag instruction, or hand-placed `[tag]` markers; tags never spoken literally/shown in transcript. Single-language is always most accurate; same-base-language variants (en-US+en-GB) incur **no** multilingual-pipeline penalty; cross-family multilingual does. Explicit warning: Cantonese/Mandarin/English mixes are hard to distinguish — recommend single-language routing via inbound webhook instead of auto-detect for these. ## 3. Testing/simulation API — CI fit for our red-team suite

Confirms and sharpens the prior pass's finding that Retell's batch-test API is the better match for `packages/templates/src/red-team/`:

- `create-test-case-definition` → `create-batch-test` (returns `batch_call_id`... actually `test_case_batch_job_id`/batch id, status `in_progress`) → poll `get-batch-test` for `status: complete` + `pass_count`/`fail_count`/`error_count`/`total_count` → `list-test-runs` for per-case results → `get-test-run` for transcript+explanation. This is a real CI-gate-able loop.
- Grading is **one pass/fail verdict per test case** (all success criteria judged together, one explanation) — NOT per-criterion like AI QA. If our red-team fixtures need per-assertion granularity (e.g., separately verifying "no PHI leaked" AND "disclosure was spoken" AND "booking succeeded"), we'd need one test case per assertion, or fall back to AI QA's per-metric grading on real/simulated calls.
- **Mocks silently fall through to production for MCP tools and any function you forget to mock** — a real risk for our adversarial fixtures if any vertical template later adds an MCP tool; the docs explicitly warn "an unmocked custom function, code tool, calendar tool, or MCP tool calls its real production endpoint during a test."
- Testing has **no discount tier** — a full red-team batch run bills at full production per-message/per-minute rates every time it's run, which should factor into how often CI runs the full suite vs. a smoke subset.

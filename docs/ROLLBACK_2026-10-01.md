# Restore point: before the agent speed optimization (2026-10-01)

Saved before any change to the 8 agents' instructions, Retell settings or the
compiler. Use it if the faster agents miss information or behave worse.

## What was saved

| What | Where |
| --- | --- |
| Code | git tag `pre-speed-optimization-2026-10-01` (commit `b6fac4b`, = `main` at the time) |
| The 8 vertical templates (all v1) | `ops_backup.agent_templates_20261001` (8 rows) |
| Every tenant's agent config (Retell agent + LLM ids, compiled config, compiler version 3) | `ops_backup.agent_configs_20261001` (21 rows) |
| Phone numbers | `ops_backup.phone_numbers_20261001` (5 rows) |

`ops_backup` is a private schema: not exposed through the API, no access for
`anon` or `authenticated`.

Template prompt fingerprints at save time (`left(md5(system_prompt), 8)`):
auto `2e1e732e`, dental `c3697cfa`, generic `8dd0af3e`, legal `1da7bd20`,
motel `3dfc970e`, real_estate `b110abce`, restaurant `86f2274d`, vet `dbede5a3`.

The old Retell agents stay alive: republishes during the optimization must
NOT pass `cleanup_superseded_agent`, so every agent id in the snapshot still
exists in Retell and can be switched back to.

## How to go back

1. **Code**: revert the optimization commits on `main`
   (`git revert <commits>`, then push; Vercel redeploys). Redeploy any edge
   function the optimization changed from the tag
   (`git checkout pre-speed-optimization-2026-10-01` in a worktree, then the
   usual `supabase functions deploy`).
2. **Templates**:
   ```sql
   update public.agent_templates t
   set system_prompt = b.system_prompt, states = b.states,
       transitions = b.transitions, global_intents = b.global_intents,
       tools = b.tools, voice_id = b.voice_id, model = b.model,
       disclosure_line = b.disclosure_line, version = b.version,
       is_active = b.is_active
   from ops_backup.agent_templates_20261001 b
   where b.id = t.id;
   ```
3. **Live agents**: point every tenant back at its old Retell agent.
   Inbound calls choose the agent from `agent_configs.retell_agent_id`
   (`voice-inbound` passes it as `override_agent_id`), so this is the switch:
   ```sql
   update public.agent_configs c
   set retell_agent_id = b.retell_agent_id, retell_llm_id = b.retell_llm_id,
       compiled_config = b.compiled_config,
       compiled_with_version = b.compiled_with_version,
       template_version = b.template_version, published_at = b.published_at
   from ops_backup.agent_configs_20261001 b
   where b.id = c.id;
   ```
   Only restore the rows of tenants that existed at save time (the join does
   that); a tenant created later keeps its own agent.
   Owners' own edits since then (assistant name, special instructions,
   transfer number) are columns this update does not touch.
4. **Phone number binding in Retell** (backup path for calls that skip the
   inbound webhook): re-point each number's `inbound_agents` to the restored
   `retell_agent_id` with `PATCH /update-phone-number/{e164}`.
5. **Check**: place a test call on one agent per vertical and confirm the
   greeting and booking flow match the old behaviour.

Delete the snapshot (`drop schema ops_backup cascade`) once the new agents
have been live and fine for a few weeks.
